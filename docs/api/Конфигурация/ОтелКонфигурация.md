# ОтелКонфигурация

Модель файла конфигурации: объекты с настройками SDK, которые заполняет разбор файла и читает фабрика.

## Описание

`ОтелКонфигурация` — корень модели файла конфигурации. Её поля хранят секции файла: ресурс, лимиты
атрибутов, пропагатор и провайдеры сигналов. Каждая секция — объект своего класса
`ОтелКонфигурация...`, все классы описаны в разделе «Поля». У классов модели есть только поля
(экспортные переменные), методов нет.

Модель создаёт [ОтелФайловаяКонфигурация.Разобрать](./ОтелФайловаяКонфигурация.md): читает файл,
подставляет переменные окружения `${...}`, проверяет `file_format`, проверяет файл по схеме
opentelemetry-configuration и заполняет поля по ключам файла.
Читает модель [ОтелКонфигурационнаяФабрика](./ОтелКонфигурационнаяФабрика.md): `Создать(Модель)`
строит по ней SDK, а `СоздатьРесурс`, `СоздатьПровайдерТрассировки`, `СоздатьПровайдерЛогирования`,
`СоздатьПровайдерМетрик` и `СоздатьПропагаторы` принимают её части: `Модель.Ресурс`,
`Модель.ПровайдерТрассировки`, `Модель.ЛимитыАтрибутов` и другие. Что фабрика строит по каждой
секции, описано на её странице; здесь — поля модели, ключи файла и значения по умолчанию.

Как `Разобрать` заполняет поля:

- ключ есть в файле — поле получает его значение. Значения уже проверены по схеме: тип, обязательные
  свойства и ограничения значений (например, число вместо строки или `schedule_delay: -1` — исключение
  `Разобрать` с путём до свойства);
- ключа нет или его значение `null` — поле сохраняет значение по умолчанию (колонка «По умолчанию» в
  таблицах);
- поле секции (тип `ОтелКонфигурация...`) равно `Неопределено`, если секции нет в файле. Секция без
  значения (например, `tracer_provider:` без вложенных ключей) — ошибка схемы: секция — объект, а у
  `tracer_provider` и `logger_provider` обязателен непустой список `processors`, у `meter_provider` —
  `readers`. Секцию без обязательных свойств со значениями по умолчанию задаёт пустой объект:
  `attribute_limits: {}`. Компонент, для которого схема допускает `null` (`otlp_http:`, `always_on:`),
  ключом без значения задаётся с настройками по умолчанию;
- поля-массивы (`Атрибуты`, `Составной`, `Процессоры`, `Читатели`, `Заголовки`) не бывают
  `Неопределено`: без ключа в файле это пустой массив. `Процессоры` и `Читатели` — массивы объектов
  модели;
- компонент, которого нет в SDK (экспортер `console`, процессор или сэмплер пользователя, читатель
  `pull`, продюсер метрик), разбор сохраняет как
  [`ОтелКонфигурацияКомпонента`](#отелконфигурациякомпонента): имя и свойства как в файле, так требует
  спецификация Configuration SDK (Parse). Фабрика на таком компоненте выбрасывает исключение (см.
  [ОтелКонфигурационнаяФабрика](./ОтелКонфигурационнаяФабрика.md), «Компоненты, которых нет в SDK»).
  Другие ключи схемы, которых нет в таблицах (например, `meter_provider.views`), разбор пропускает без
  предупреждения. Ключ, которого нет в схеме, — ошибка, кроме файла с более новой младшей версией
  `file_format` (см. [ОтелФайловаяКонфигурация](./ОтелФайловаяКонфигурация.md), «Проверка по схеме»).

Модель можно изменить в коде перед вызовом фабрики: фабрика читает поля в момент вызова и ничего не
запоминает. Так можно, например, заменить адрес экспортера или сэмплер после разбора файла (см.
«Пример»). Изменения модели после `Создать` построенный SDK не меняют.
`ОтелАвтоконфигурация.Инициализировать()` по переменной `OTEL_CONFIG_FILE` вызывает `Разобрать` и
`Создать` сама и модель не возвращает. Чтобы изменить модель, вызовите обе функции в своём коде и
зарегистрируйте SDK через `ОтелГлобальный.Установить`.

Объекты модели можно создать и без файла, через `Новый` (см. «Конструктор»). Фабрика проверяет такую
модель по схеме так же, как `Разобрать` проверяет файл (Configuration SDK, Create; см.
[ОтелФайловаяКонфигурация.ПроверитьМодель](./ОтелФайловаяКонфигурация.md#проверитьмодель)): без
`ФорматФайла` или с версией не `1.x`, без `Экспортер` у процессора или читателя, с провайдером без
процессоров или читателей, с числом вне границ схемы (например, `ЗадержкаОтправки = -1`), значением не
из перечисления или значением не того типа она выбрасывает исключение с путём свойства схемы. Модель
`Новый ОтелКонфигурация()` с одним заполненным полем `ФорматФайла = "1.0"` даёт SDK с no-op
провайдерами сигналов и [ОтелНоопПропагатор](../Пропагация/ОтелНоопПропагатор.md) — как файл с одним
ключом `file_format`.

`Неопределено` в поле модели — значение null: фабрика берёт значение по умолчанию из колонки «По
умолчанию», как требует спецификация Configuration SDK (Create) для свойства со значением null.
Например, `Интервал = Неопределено` у периодического читателя — интервал 60000 мс. Фабрика работает с
копией модели и саму модель не меняет. Поле, у которого значения по умолчанию нет (в колонке
`Неопределено`), остаётся не заданным.

Ключи файла и поля модели:

```yaml
file_format: "1.0"                    # ФорматФайла
disabled: false                       # Отключен
resource:                             # Ресурс
  attributes:                         #   Атрибуты
    - name: service.name
      value: мой-сервис
  attributes_list: env=prod           #   СписокАтрибутов
  schema_url: https://opentelemetry.io/schemas/1.26.0  #   АдресСхемы
attribute_limits:                     # ЛимитыАтрибутов
  attribute_count_limit: 64           #   МаксКоличествоАтрибутов
propagator:                           # Пропагатор
  composite:                          #   Составной
    - tracecontext:
    - baggage:
tracer_provider:                      # ПровайдерТрассировки
  processors:                         #   Процессоры
    - batch:
        schedule_delay: 5000          #     ЗадержкаОтправки
        exporter:
          otlp_http:                  #     Экспортер
            endpoint: http://localhost:4318/v1/traces   # Адрес
  limits:                             #   Лимиты
    event_count_limit: 64             #     МаксСобытий
  sampler:                            #   Сэмплер
    parent_based:                     #     Тип
      root:                           #     Корневой
        trace_id_ratio_based:         #       Тип
          ratio: 0.1                  #       Доля
meter_provider:                       # ПровайдерМетрик
  exemplar_filter: trace_based        #   ФильтрЭкземпляров
  readers:                            #   Читатели
    - periodic:
        interval: 60000               #     Интервал
        exporter:
          otlp_http:                  #     Экспортер
            endpoint: http://localhost:4318/v1/metrics
            temporality_preference: delta
logger_provider:                      # ПровайдерЛогирования
  processors:                         #   Процессоры
    - batch:
        exporter:
          otlp_http:
            endpoint: http://localhost:4318/v1/logs
```

## Конструктор

```bsl
Новый ОтелКонфигурация()
Новый ОтелКонфигурацияРесурса()
Новый ОтелКонфигурацияЛимитовАтрибутов()
Новый ОтелКонфигурацияПропагатора()
Новый ОтелКонфигурацияПровайдераТрассировки()
Новый ОтелКонфигурацияЛимитовСпана()
Новый ОтелКонфигурацияСэмплера()
Новый ОтелКонфигурацияПровайдераМетрик()
Новый ОтелКонфигурацияПровайдераЛогирования()
Новый ОтелКонфигурацияПакетногоПроцессора()
Новый ОтелКонфигурацияПростогоПроцессора()
Новый ОтелКонфигурацияПериодическогоЧитателя()
Новый ОтелКонфигурацияЛимитовМощности()
Новый ОтелКонфигурацияЭкспортераOtlpHttp()
Новый ОтелКонфигурацияЭкспортераOtlpGrpc()
Новый ОтелКонфигурацияКомпонента()
```

Параметров у конструкторов нет: поля получают значения из колонки «По умолчанию». Это те же
значения, что получает поле при разборе файла без своего ключа. Исключение — `ЗадержкаОтправки`
пакетного процессора: значение по умолчанию у спанов и записей лога разное, поэтому у объекта из
`Новый` она `Неопределено` и фабрика берёт 5000 мс для спанов и 1000 мс для записей лога; разбор
файла без ключа сразу заполняет 5000 или 1000.

## Поля

В таблицах «Ключ в файле» — ключ внутри секции, которой соответствует класс; «По умолчанию» —
значение поля у нового объекта, оно же остаётся у поля, если ключа нет в файле.

### ОтелКонфигурация

Весь файл. Объект возвращает `ОтелФайловаяКонфигурация.Разобрать`, принимает
`ОтелКонфигурационнаяФабрика.Создать`.

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `ФорматФайла` | `Строка` | `""` | `file_format` | Версия формата файла. `Разобрать` требует этот ключ и принимает только версии `1.x`. Пишите версию в кавычках: `1.0` без кавычек YAML читает как число 1, и разбор выбрасывает исключение. Обязательное поле: модель без него или с версией не `1.x` фабрика не создаёт — выбрасывает исключение |
| `Отключен` | `Булево` | `Ложь` | `disabled` | `Истина` — фабрика создаёт SDK, который не экспортирует телеметрию, и не читает остальные поля. Значение по схеме — булево: подстановка `${OTEL_SDK_DISABLED}` без кавычек даёт булево значение, пустая — `null` (`Ложь`), другая строка — ошибка разбора |
| `Ресурс` | [`ОтелКонфигурацияРесурса`](#отелконфигурацияресурса), `Неопределено` | `Неопределено` | `resource` | Ресурс SDK; `Неопределено` — ресурс по умолчанию |
| `ЛимитыАтрибутов` | [`ОтелКонфигурацияЛимитовАтрибутов`](#отелконфигурациялимитоватрибутов), `Неопределено` | `Неопределено` | `attribute_limits` | Общие лимиты атрибутов спанов и записей логов; `Неопределено` — не заданы |
| `Пропагатор` | [`ОтелКонфигурацияПропагатора`](#отелконфигурацияпропагатора), `Неопределено` | `Неопределено` | `propagator` | Пропагаторы SDK; `Неопределено` — пропагация отключена (`ОтелНоопПропагатор`) |
| `ПровайдерТрассировки` | [`ОтелКонфигурацияПровайдераТрассировки`](#отелконфигурацияпровайдератрассировки), `Неопределено` | `Неопределено` | `tracer_provider` | Провайдер трассировки; `Неопределено` — SDK получает no-op провайдер трассировки |
| `ПровайдерМетрик` | [`ОтелКонфигурацияПровайдераМетрик`](#отелконфигурацияпровайдераметрик), `Неопределено` | `Неопределено` | `meter_provider` | Провайдер метрик; `Неопределено` — SDK получает no-op провайдер метрик |
| `ПровайдерЛогирования` | [`ОтелКонфигурацияПровайдераЛогирования`](#отелконфигурацияпровайдералогирования), `Неопределено` | `Неопределено` | `logger_provider` | Провайдер логирования; `Неопределено` — SDK получает no-op провайдер логирования |

### ОтелКонфигурацияРесурса

Секция `resource`, поле `ОтелКонфигурация.Ресурс`. Ресурс по ней создаёт
`ОтелКонфигурационнаяФабрика.СоздатьРесурс`.

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `Атрибуты` | `Массив` из `Структура` | пустой массив | `attributes` | Атрибуты ресурса — структуры с полями `Имя` (`Строка`, из `name`), `Значение` (из `value` без преобразования: строка, число, булево или массив, как прочитал YAML; `value: null` — `Неопределено`) и `Тип` (из `type`: `string`, `bool`, `int`, `double`, `string_array`, `bool_array`, `int_array`, `double_array`; без `type` — `Неопределено`, тип `string`). Фабрика проверяет, что значение соответствует типу: строка, булево, целое число, число или непустой массив значений своего типа; иначе — исключение. Атрибут со значением `Неопределено` фабрика пропускает: он не перекрывает атрибут из `СписокАтрибутов`. У структуры, собранной в коде, поля `Тип` может не быть — тип `string` |
| `СписокАтрибутов` | `Строка` | `""` | `attributes_list` | Атрибуты строкой в формате `OTEL_RESOURCE_ATTRIBUTES`: `key1=value1,key2=value2`, значения в percent-encoding. При совпадении ключей важнее `Атрибуты`. Строка, которая не разбирается в этом формате, — исключение фабрики |
| `АдресСхемы` | `Строка` | `""` | `schema_url` | URL схемы ресурса; `""` — не задан |

### ОтелКонфигурацияЛимитовАтрибутов

Секции `attribute_limits` (поле `ОтелКонфигурация.ЛимитыАтрибутов`) и `logger_provider.limits`
(поле `Лимиты` [провайдера логирования](#отелконфигурацияпровайдералогирования)).

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `МаксДлинаЗначенияАтрибута` | `Число`, `Неопределено` | `Неопределено` | `attribute_value_length_limit` | Максимальная длина значения атрибута; `Неопределено` — не задана |
| `МаксГлубинаЗначенияАтрибута` | `Число`, `Неопределено` | `Неопределено` | `attribute_value_depth_limit` | Максимальная глубина значения атрибута: глубина верхнего значения — 1, массивы и соответствия глубже лимита заменяются пустым значением. Не меньше 1; `Неопределено` — не задана |
| `МаксКоличествоАтрибутов` | `Число`, `Неопределено` | `Неопределено` | `attribute_count_limit` | Максимальное количество атрибутов; `Неопределено` — не задано |

Лимит, заданный в `limits` провайдера (`tracer_provider.limits`, `logger_provider.limits`),
перекрывает такой же лимит `attribute_limits`, как требует схема файла; лимит, не заданный в
`limits`, фабрика берёт из `attribute_limits` (см. `СоздатьПровайдерТрассировки` и
`СоздатьПровайдерЛогирования` на странице фабрики). Не заданное нигде количество атрибутов — 128,
длина значения — без ограничения, глубина значения — 64.

`ОтелКонфигурационнаяФабрика.СоздатьПропагаторы`.

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `Составной` | `Массив` из [`ОтелКонфигурацияКомпонента`](#отелконфигурациякомпонента) | пустой массив | `composite` | Пропагаторы: элемент списка — объект с одним ключом, именем пропагатора (`- tracecontext:`); `Имя` — этот ключ, `Свойства` — значение под ним |
| `СписокСоставного` | `Строка` | `""` | `composite_list` | Имена пропагаторов через запятую, как в `OTEL_PROPAGATORS`; фабрика добавляет их после имён из `Составной` |

### ОтелКонфигурацияПровайдераТрассировки

Секция `tracer_provider`, поле `ОтелКонфигурация.ПровайдерТрассировки`. Провайдер по ней создаёт
`ОтелКонфигурационнаяФабрика.СоздатьПровайдерТрассировки`.

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `Процессоры` | `Массив` из [`ОтелКонфигурацияПакетногоПроцессора`](#отелконфигурацияпакетногопроцессора), [`ОтелКонфигурацияПростогоПроцессора`](#отелконфигурацияпростогопроцессора), [`ОтелКонфигурацияКомпонента`](#отелконфигурациякомпонента) | пустой массив | `processors` | Процессоры спанов по элементам списка в порядке файла: `- batch:`, `- simple:`; процессор, которого нет в SDK, — `ОтелКонфигурацияКомпонента`. | `Лимиты` | [`ОтелКонфигурацияЛимитовСпана`](#отелконфигурациялимитовспана), `Неопределено` | `Неопределено` | `limits` | Лимиты спана; `Неопределено` — лимиты из `attribute_limits` и значения по умолчанию |
| `Сэмплер` | [`ОтелКонфигурацияСэмплера`](#отелконфигурациясэмплера), [`ОтелКонфигурацияКомпонента`](#отелконфигурациякомпонента), `Неопределено` | `Неопределено` | `sampler` | Сэмплер; `Неопределено` — `parent_based` с корневым `always_on`; сэмплер, которого нет в SDK, — `ОтелКонфигурацияКомпонента` |
| `ГенераторИд` | [`ОтелКонфигурацияКомпонента`](#отелконфигурациякомпонента), `Неопределено` | `Неопределено` | `id_generator` | Генератор trace ID и span ID, в SDK есть `random`; `Неопределено` — `random` |

### ОтелКонфигурацияЛимитовСпана

Секция `tracer_provider.limits`, поле `Лимиты`
[провайдера трассировки](#отелконфигурацияпровайдератрассировки). Фабрика создаёт по ней
[ОтелЛимитыСпана](../Трассировка/ОтелЛимитыСпана.md). Как первые три поля сочетаются с
`attribute_limits`, см. [ОтелКонфигурацияЛимитовАтрибутов](#отелконфигурациялимитоватрибутов).

| Поле | Тип | По умолчанию | Ключ в файле | Описание |

sampler:

Ключ `exporter.otlp_grpc` процессора и периодического читателя. Фабрика создаёт по нему
[ОтелGrpcТранспорт](../Экспорт/ОтелGrpcТранспорт.md) и экспортер сигнала. Ключ без значения
(`otlp_grpc:`) задаёт экспортер с настройками по умолчанию. Поля те же, что у
[`ОтелКонфигурацияЭкспортераOtlpHttp`](#отелконфигурацияэкспортераotlphttp), кроме адреса, сжатия и
размера ответа; кодирования у `otlp_grpc` нет — сообщения gRPC всегда protobuf:

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `Адрес` | `Строка` | `""` | `endpoint` | Адрес коллектора без пути сигнала: URL со схемой `http` или `https`, например `http://collector:4317`, или адрес без схемы (`collector:4317`) — соединение с TLS, при `tls.insecure: true` — без TLS. Сервис сигнала gRPC-транспорт выбирает сам. Адрес с другой схемой — исключение фабрики; `""` — `http://localhost:4317` |
| `Сжатие` | `Строка` | `""` | `compression` | Сжатие клиент OPI_GRPC не поддерживает ([OpenIntegrations#112](https://github.com/Bayselonarrend/OpenIntegrations/issues/112)): при `gzip` фабрика пишет предупреждение в лог, данные отправляются без сжатия. `none` и `""` — без сжатия, другое значение — исключение фабрики |
| `Таймаут` | `Число` | `10000` | `timeout` | Срок каждого экспорта вместе с повторами и таймаут вызова gRPC, мс; `0` — без ограничения |
| `Заголовки` | `Массив` из `Структура` | пустой массив | `headers` | Метаданные вызова gRPC — структуры с полями `Имя` и `Значение`, как у `otlp_http` |
| `СписокЗаголовков` | `Строка` | `""` | `headers_list` | Метаданные строкой в формате `OTEL_EXPORTER_OTLP_HEADERS`. При совпадении имён действует значение из `Заголовки` |
| `ПредпочтениеВременнойАгрегации` | `Строка` | `""` | `temporality_preference` | Временная агрегация метрик, как у `otlp_http` |
| `АгрегацияГистограммПоУмолчанию` | `Строка` | `""` | `default_histogram_aggregation` | Агрегация гистограмм по умолчанию, как у `otlp_http` |
| `МаксРазмерЗапроса` | `Число` | `67108864` | `max_request_size` | Наибольший размер сообщения запроса до сжатия, байт, как у `otlp_http`; `0` — без ограничения |
| `МаксРазмерОтвета` | `Число` | `4194304` | `max_response_size` | Клиент OPI_GRPC принимает ответ не больше 4 MiB, другой лимит задать нельзя ([OpenIntegrations#113](https://github.com/Bayselonarrend/OpenIntegrations/issues/113)): при другом значении фабрика пишет предупреждение в лог, действует лимит 4 MiB |
| `НастройкиTls` | [`ОтелНастройкиTls`](../Экспорт/ОтелНастройкиTls.md), `Неопределено` | `Неопределено` | `tls` | Файлы TLS, как у `otlp_http`, и `Insecure` (`insecure`): `Истина` — соединение без TLS с адресом без схемы. Сертификат сервера транспорт проверяет по `ФайлСертификата`; клиентский ключ и сертификат (mTLS) клиент OPI_GRPC не поддерживает ([OpenIntegrations#102](https://github.com/Bayselonarrend/OpenIntegrations/issues/102)) — транспорт предупреждает в логе |

### ОтелКонфигурацияКомпонента

Компонент, заданный в файле ключом-именем со свойствами под ним:

- пропагатор — элемент списка `propagator.composite` (`- tracecontext:`);
- генератор ID — секция `tracer_provider.id_generator` (`random:`);
- компонент, которого нет в SDK, на месте экспортера, процессора, читателя, продюсера метрик или
  сэмплера, например экспортер `console`, читатель `pull` или экспортер пользователя:

```yaml
exporter:
  my_exporter:            # Имя
    url: http://example   # Свойства
```

Спецификация Configuration SDK (Parse) требует сохранять конфигурацию компонента, которого нет в SDK,
в общем виде; фабрика на таком компоненте выбрасывает исключение (см.
[ОтелКонфигурационнаяФабрика](./ОтелКонфигурационнаяФабрика.md), «Компоненты, которых нет в SDK»).

| Поле | Тип | По умолчанию | Ключ в файле | Описание |
|------|-----|--------------|--------------|----------|
| `Имя` | `Строка` | `""` | ключ компонента | Имя компонента, например `tracecontext`, `console`, `my_exporter` |
| `Свойства` | `Соответствие`, `Неопределено` | `Неопределено` | значение под ключом | Свойства компонента как в файле — `Соответствие`, значения которого прочитаны из YAML без преобразования; `Неопределено` — ключ без значения (`console:`) |

## Пример

```bsl
#Использовать opentelemetry

Модель = ОтелФайловаяКонфигурация.Разобрать("/etc/otel/config.yaml");

// Секции tracer_provider может не быть в файле: тогда SDK получает no-op провайдер трассировки
Провайдер = Модель.ПровайдерТрассировки;
Если Провайдер <> Неопределено Тогда

    // Другой адрес у экспортеров otlp_http всех процессоров спанов
    Для Каждого Процессор Из Провайдер.Процессоры Цикл
        Если ТипЗнч(Процессор) <> Тип("ОтелКонфигурацияКомпонента")
            И ТипЗнч(Процессор.Экспортер) = Тип("ОтелКонфигурацияЭкспортераOtlpHttp") Тогда
            Процессор.Экспортер.Адрес = "http://collector:4318/v1/traces";
        КонецЕсли;
    КонецЦикла;

    // Сэмплер parent_based: 10% новых трассировок
    Корневой = Новый ОтелКонфигурацияСэмплера();
    Корневой.Тип = "trace_id_ratio_based";
    Корневой.Доля = 0.1;
    Сэмплер = Новый ОтелКонфигурацияСэмплера();
    Сэмплер.Тип = "parent_based";
    Сэмплер.Корневой = Корневой;
    Провайдер.Сэмплер = Сэмплер;

КонецЕсли;

// Фабрика читает поля модели в момент вызова и проверяет измененную модель по схеме
Сдк = ОтелКонфигурационнаяФабрика.Создать(Модель);
ОтелГлобальный.Установить(Сдк);
// ...
Сдк.Закрыть();
```

```bsl
// Модель без файла: спаны отправляются по OTLP/HTTP, пропагаторы W3C
Экспортер = Новый ОтелКонфигурацияЭкспортераOtlpHttp();
Экспортер.Адрес = "http://collector:4318/v1/traces";

Процессор = Новый ОтелКонфигурацияПакетногоПроцессора();
Процессор.Экспортер = Экспортер;

Модель = Новый ОтелКонфигурация();
Модель.ФорматФайла = "1.0";
Модель.Ресурс = Новый ОтелКонфигурацияРесурса();
Модель.Ресурс.Атрибуты.Добавить(Новый Структура("Имя, Значение", "service.name", "мой-сервис"));
Модель.ПровайдерТрассировки = Новый ОтелКонфигурацияПровайдераТрассировки();
Модель.ПровайдерТрассировки.Процессоры.Добавить(Процессор);
Модель.Пропагатор = Новый ОтелКонфигурацияПропагатора();
Модель.Пропагатор.СписокСоставного = "tracecontext,baggage";

// Секций meter_provider и logger_provider нет: у SDK только провайдер трассировки
Сдк = ОтелКонфигурационнаяФабрика.Создать(Модель);
```
