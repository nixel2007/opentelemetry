# ОтелПрометеусЧитательМетрик

Prometheus-читатель метрик — экспортирует метрики в форматах Prometheus text и OpenMetrics.

## Описание

`ОтелПрометеусЧитательМетрик` реализует pull-модель сбора метрик для Prometheus.
Метрики собираются по запросу и возвращаются в формате [Prometheus text exposition](https://prometheus.io/docs/instrumenting/exposition_formats/)
или [OpenMetrics 1.0](https://github.com/prometheus/OpenMetrics/blob/v1.0.0/specification/OpenMetrics.md),
выбранном по заголовку `Accept` (см. [Форматы выдачи](#форматы-выдачи)). Выдачу формирует сам
читатель, без сторонней клиентской библиотеки.

Всегда использует кумулятивную временную агрегацию (`Cumulative`).

### Форматы выдачи

Формат выбирается по заголовку `Accept` ([Prometheus Content Negotiation](https://prometheus.io/docs/instrumenting/content_negotiation/)):
из поддерживаемых форматов берётся формат с наибольшим весом `q`, при равных весах — указанный
раньше. Без заголовка или если ни один формат не поддерживается — text format 0.0.4.

| Accept | Формат | Content-Type ответа |
|---|---|---|
| нет, `*/*`, `text/*`, `text/plain` | text 0.0.4 | `text/plain; version=0.0.4; charset=utf-8` |
| `text/plain;version=1.0.0` | text 1.0.0 | `text/plain; version=1.0.0; charset=utf-8; escaping=underscores` |
| `application/openmetrics-text;version=1.0.0` | OpenMetrics 1.0.0 | `application/openmetrics-text; version=1.0.0; charset=utf-8; escaping=underscores` |
| `application/openmetrics-text` | OpenMetrics 0.0.1 | `application/openmetrics-text; version=0.0.1; charset=utf-8` |

Отличия OpenMetrics от text format:

- у семейства счётчика нет суффикса `_total` (`# TYPE jobs counter`), у сэмпла — всегда есть;
- выводится `# UNIT`, если имя семейства оканчивается на суффикс единицы: `# UNIT http_duration_seconds seconds`;
- время старта точки (`StartTimeUnixNano`) выводится сэмплом `_created` у счётчиков и гистограмм;
- есть типы `info`, `unknown` и `stateset` (см. [Подсказка типа датчика](#подсказка-типа-датчика));
- у сэмпла счётчика и у бакетов гистограммы выводятся exemplars (см. [Exemplars](#exemplars));
- выдача завершается строкой `# EOF`.

```
# HELP jobs Задания
# TYPE jobs counter
jobs_total{otel_scope_name="fmt-lib"} 2 # {span_id="b7ad6b7169203331",trace_id="0af7651916cd43dd8448eb211c80319c"} 1 1700000000.5
jobs_created{otel_scope_name="fmt-lib"} 1700000000
# EOF
```

### Экранирование имён

Параметр `escaping` в `Accept` задаёт схему экранирования имён метрик и лейблов. Она применяется
после перевода имён OTel в имена Prometheus (второй перевод имён):

| `escaping` | Правило | `foo.bar_baz` |
|---|---|---|
| `underscores` (по умолчанию) | недопустимые символы заменяются на `_` | `foo_bar_baz` |
| `dots` | `_` → `__`, `.` → `_dot_`, прочие недопустимые → `__` | `foo_dot_bar__baz` |
| `values` | имя вне классического формата получает префикс `U__`, `_` → `__`, символ → `_<код hex>_` | `U__foo_2e_bar__baz` |
| `allow-utf-8` | имя не меняется, в выдаче берётся в кавычки: `{"foo.bar_baz"}` | `foo.bar_baz` |

`allow-utf-8` допустим только в форматах версии 1.0.0; для других версий используется `underscores`.

### Имена метрик

Перевод имён OTel в имена Prometheus выполняется только в этом читателе: имена и единицы
инструментов, а также OTLP-экспорт не меняются. По спецификации
[Prometheus and OpenMetrics Compatibility](https://opentelemetry.io/docs/specs/otel/compatibility/prometheus_and_openmetrics/)
(стратегия `UnderscoreEscapingWithSuffixes`, других стратегий трансляции нет):

- недопустимые символы имени заменяются на `_`: `http.server.requests` → `http_server_requests`;
- единица UCUM переводится в слово Prometheus и добавляется суффиксом перед суффиксом типа:
  `s` → `_seconds`, `By` → `_bytes`, `%` → `_percent` (полная таблица — в спецификации);
- части единицы в фигурных скобках отбрасываются (`{request}` суффикса не даёт),
  скорость `X/Y` становится `X_per_Y` (`By/s` → `_bytes_per_second`), безразмерная `1` суффикса не даёт;
- суффикс не добавляется, если имя уже оканчивается на эту единицу;
- к монотонной сумме (Counter) добавляется `_total`, если имя им ещё не оканчивается.
  Строки `# HELP` и `# TYPE` счётчика в text format 0.0.4 относятся к имени сэмпла: `# TYPE http_requests_total counter`.

| Инструмент OTel | Имя сэмпла Prometheus |
|---|---|
| Гистограмма `http.server.request.duration`, `s` | `http_server_request_duration_seconds_bucket` / `_sum` / `_count` |
| Счётчик `net.io`, `By` | `net_io_bytes_total` |
| Счётчик `http.requests`, `{request}` | `http_requests_total` |
| Датчик `cpu.utilization`, `1` | `cpu_utilization` |

Затем имена экранируются по схеме из `Accept` (см. [Экранирование имён](#экранирование-имён)),
поэтому выдача всегда соответствует согласованному формату. Счётчик `foo.bar` с единицей `By`
выводится как `foo_bar_bytes_total` и без `escaping`, и с `escaping=allow-utf-8`. Имена лейблов
переводятся так же.

Одноимённые метрики объединяются в одно семейство. Метрика с другим TYPE пропускается целиком,
в том числе когда совпадает только имя в строке `# TYPE`: счётчик `foo` с единицей `By`
(`# TYPE foo_bytes_total counter`) и датчик `foo_bytes_total`.
Точка отбрасывается, если сэмпл с тем же именем и набором лейблов уже есть в выдаче, в том числе
в другом семействе. Например, так бывает у метрик `a.b` и `a_b` одной области или у счётчика `foo`
с единицей `By` (сэмпл `foo_bytes_total`) и датчика `foo_bytes_total`. В обоих случаях в лог пишется
предупреждение.

### Лейблы атрибутов

Атрибуты точек становятся лейблами (спецификация, раздел Metric Attributes):

- в имени лейбла символы вне `[a-zA-Z0-9_]`, включая `:`, заменяются на `_`: `http:method` → `http_method`;
- строковое значение выводится как есть, остальные — в JSON: `true`/`false`, `2.5`, `["x","y"]`;
- если ключи совпали после замены символов (`a.b` и `a_b`), значения склеиваются через `;`
  в порядке исходных ключей: `a_b="first;second"`.

### Лейблы области

На каждый сэмпл добавляются лейблы области инструментирования (спецификация, раздел Instrumentation Scope):

| Лейбл | Значение |
|---|---|
| `otel_scope_name` | имя области |
| `otel_scope_version` | версия области |
| `otel_scope_schema_url` | адрес схемы области |
| `otel_scope_<атрибут>` | атрибуты области, имя лейбла нормализуется как у атрибутов точек |

Пустые имя, версия и адрес схемы лейбла не дают. Атрибут области, который после префикса совпадает
с `otel_scope_name`, `otel_scope_version` или `otel_scope_schema_url`, отбрасывается. Поэтому серии
метров с одинаковыми именем и версией, но разными адресами схемы или атрибутами не склеиваются.

### Атрибуты ресурса

Ресурс отдельной метрикой (`target_info`) не выводится: этот раздел спецификации (Resource
Attributes) в статусе Development. По умолчанию атрибуты ресурса в лейблы метрик не копируются;
`УстановитьАтрибутыРесурсаВЛейблах` копирует выбранные атрибуты.

### Подсказка типа датчика

Датчик и немонотонная сумма выводятся по подсказке `prometheus.type` из метаданных метрики
(`ОтелДанныеМетрики.Метаданные()`, спецификация, раздел Gauges). Метаданные задаёт источник данных,
например производитель метрик, переносящий метрики Prometheus.

| `prometheus.type` | OpenMetrics | text format |
|---|---|---|
| нет, `gauge`, другое значение | `gauge` | `gauge` |
| `unknown` (и `unkown`) | `unknown` | `untyped` |
| `info` | `info`, сэмпл `<имя>_info`, значение `1` | `gauge` `<имя>_info`, значение `1` |
| `stateset` | `stateset` | `gauge` |

### Сводки (Summary)

Сводка ([ОтелТипМетрики.Сводка](./ОтелТипМетрики.md), обычно от продюсера метрик) выводится
Prometheus summary (спецификация, раздел Summaries): квантили — сэмплами с лейблом `quantile` по
возрастанию квантиля, затем `_sum` и `_count`, в OpenMetrics — ещё `_created`. Exemplars сводки не
выводятся.

```
# TYPE rpc_duration_seconds summary
rpc_duration_seconds{quantile="0.5"} 0.2
rpc_duration_seconds{quantile="0.99"} 0.9
rpc_duration_seconds_sum 5.5
rpc_duration_seconds_count 12
```

### Exemplars

В OpenMetrics exemplars выводятся у сэмпла счётчика и у бакетов гистограммы (спецификация,
раздел Exemplars): у счётчика — последний по времени exemplar точки, у бакета — последний exemplar,
значение которого попало в бакет. Лейблы exemplar — `trace_id`, `span_id` и отфильтрованные атрибуты;
атрибуты отбрасываются, если вместе с `trace_id` и `span_id` длина имён и значений лейблов больше
128 символов (лимит OpenMetrics). Exemplars датчиков и text format не выводятся.

### Отброшенные данные

О любой отброшенной метрике, точке или метаданных в лог пишется предупреждение: конфликт TYPE,
повторный сэмпл, экспоненциальная гистограмма (форматы text и OpenMetrics её не поддерживают), ошибка
перевода метрики, описание или единица метрики, отличные от `# HELP` или `# UNIT` семейства, в
которое она добавлена.

### Отдача по HTTP

HTTP-сервера в читателе нет: метрики отдаёт приложение. Из своего HTTP-обработчика `/metrics`
(например, контроллера Winow) вызовите
`СобратьДляЗапроса` с заголовком `Accept` запроса. Либо зарегистрируйте читатель в реестре
библиотеки `prometheus` (`Collect`) и отдавайте реестр, например, через
[prometheus-metrics](https://autumn-library.github.io/prometheus-metrics/).

## Конструктор

Без параметров. Создаётся через [ОтелПостроительПровайдераМетрик](./ОтелПостроительПровайдераМетрик.md).

### ДобавитьМетр

Регистрирует метр в читателе.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `Метр` | `ОтелМетр` | — | Метр для регистрации |

### ДобавитьПродюсер

Регистрирует продюсер внешних метрик (MetricProducer): его метрики, например сводки (Summary) из
мостов к другим библиотекам, выдаются вместе с метриками метров. Продюсер получает фильтр метрик
читателя с предпочтительной кумулятивной временной агрегацией. Сбой продюсера (исключение или
статус ошибки) логируется, делает результат сбора ошибкой и не лишает выдачу остальных метрик.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `Продюсер` | `ИнтерфейсПродюсерМетрик` | — | Продюсер метрик |

---

### СобратьДляЗапроса

Собирает все метрики в формате, согласованном по заголовку `Accept` (см. [Форматы выдачи](#форматы-выдачи)),
и возвращает тело ответа и его `Content-Type`. Сбой сбора одного метра или инструмента логируется
и не лишает выдачу метрик остальных; о сбое сообщает `РезультатСбора`. После `Закрыть` метрик нет.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `Accept` | `Строка`, `Неопределено` | `""` | Значение заголовка `Accept` запроса |
| `ТипКонтента` | `Строка` | `""` | Выходной параметр: `Content-Type` ответа |
| `РезультатСбора` | `ОтелРезультатЭкспорта` | `Неопределено` | Выходной параметр: ошибка, если сбор метра или инструмента завершился сбоем (их метрики не попадают в выдачу) или читатель закрыт; иначе успех |

**Возвращает:** `Строка` — тело ответа

---

### СобратьВТексте

Собирает все метрики и возвращает их в формате Prometheus text 0.0.4 (то же, что
`СобратьДляЗапроса` без `Accept`). После `Закрыть` возвращает пустую строку.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `РезультатСбора` | `ОтелРезультатЭкспорта` | `Неопределено` | Выходной параметр: см. `СобратьДляЗапроса` |

**Возвращает:** `Строка` — метрики в формате Prometheus text exposition 0.0.4

| Параметр | Тип | По умолчанию | Описание |

### СобратьСемейства

Собирает все метрики как семейства в промежуточном формате библиотеки `prometheus`: `Соответствие`
с ключами `Имя`, `Тип`, `Справка`, `Сэмплы` (у сэмпла — `ИмяСэмпла`, `Лейблы`, `Значение`) и
`Единица`, если у метрики есть единица (слово Prometheus, например `seconds`).

`Имя` — имя метрики в строках `# HELP` и `# TYPE`. У счётчика оно совпадает с именем сэмпла
(`http_requests_total` при стратегии с суффиксами), у гистограммы это имя без `_bucket`, `_sum` и `_count`.
Результат можно передать в `Prometheus.СериализоватьВТекст`: текст будет тот же, что у `СобратьВТексте`.
После `Закрыть` возвращает пустой массив.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `РезультатСбора` | `ОтелРезультатЭкспорта` | `Неопределено` | Выходной параметр: ошибка, если сбор метра или инструмента завершился сбоем (их метрики не попадают в выдачу) или читатель закрыт; иначе успех |

**Возвращает:** `Массив` — массив семейств метрик Prometheus

### Collect

Возвращает семейства метрик (`СобратьСемейства`) для реестра библиотеки `prometheus`: читатель
регистрируется в `CollectorRegistry` как custom Collector и выдаётся вместе с метриками библиотеки.
Библиотека `prometheus` не входит в зависимости `opentelemetry` (выдачу формирует сам читатель):
чтобы использовать её реестр, подключите библиотеку в своём проекте (`#Использовать prometheus`).

```bsl
Реестр = Prometheus.РеестрПоУмолчанию();
Реестр.Register(ПрометеусЧитатель);
Текст = Prometheus.СериализоватьВТекст(Prometheus.СобратьМетрики(Реестр));
```

**Возвращает:** `Массив` — массив семейств метрик Prometheus

---

### УстановитьАтрибутыРесурсаВЛейблах

Включает копирование атрибутов ресурса в лейблы метрик (`resource_constant_labels`). По умолчанию
атрибуты ресурса не копируются. Атрибут точки с тем же именем лейбла приоритетнее атрибута ресурса.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `Включаемые` | `Массив`, `Неопределено` | — | Шаблоны ключей включаемых атрибутов: `*` — любые символы, `?` — один символ; `Неопределено` — все атрибуты |
| `Исключаемые` | `Массив`, `Неопределено` | `Неопределено` | Шаблоны ключей исключаемых атрибутов, приоритетнее включаемых |

```bsl
Включаемые = Новый Массив();
Включаемые.Добавить("service.*");
Исключаемые = Новый Массив();
Исключаемые.Добавить("service.instance.id");
ПрометеусЧитатель.УстановитьАтрибутыРесурсаВЛейблах(Включаемые, Исключаемые);
```

### Закрыть

Очищает зарегистрированные метры и продюсеры. После закрытия сбор возвращает пустой результат с
ошибкой, сброс буфера — ошибку.

**Возвращает:** `ОтелРезультатЗакрытия` — успех; повторный вызов — ошибка «Reader закрыт»

---

### ЛимитМощности

Возвращает лимит мощности (cardinality limit) читателя по умолчанию для всех видов инструментов.
У каждого читателя свои потоки метрик, поэтому лимит действует только на данные этого читателя.

**Возвращает:** `Число` — `2000` (значение по умолчанию из спецификации)

---

### ЛимитМощностиДляВида

Возвращает лимит мощности читателя для вида инструмента: заданный `УстановитьЛимитМощностиДляВида`
или общий `ЛимитМощности()`. Применяется к потокам, для которых View не задал лимит.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ВидИнструмента` | `Строка` | — | `Counter`, `Histogram`, `ObservableGauge`, ... |

**Возвращает:** `Число`

---

### УстановитьЛимитМощностиДляВида

Задаёт лимит мощности читателя для вида инструмента. Действует для инструментов, созданных после вызова.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ВидИнструмента` | `Строка` | — | Вид инструмента |
| `Лимит` | `Число` | — | Лимит мощности |

### АгрегацияПоУмолчанию

Возвращает агрегацию читателя по умолчанию для вида инструмента (агрегация по умолчанию
настраивается функцией вида инструмента). Применяется к потокам, для которых View не задал агрегацию.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ВидИнструмента` | `Строка` | — | Вид инструмента |

**Возвращает:** `Строка`, `Соответствие` — заданная агрегация; `"default"` — агрегация спецификации для вида

---

### УстановитьАгрегациюПоУмолчанию

Задаёт агрегацию читателя по умолчанию для вида инструмента. Действует для инструментов,
созданных после вызова.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ВидИнструмента` | `Строка` | — | Вид инструмента |
| `Агрегация` | `Строка`, `Соответствие` | — | Агрегация (`ОтелАгрегация.Сумма()`, `"drop"`, ...) |

```bsl
ПрометеусЧитатель = Новый ОтелПрометеусЧитательМетрик();
ПрометеусЧитатель.УстановитьАгрегациюПоУмолчанию("UpDownCounter", "drop");
```

---

### АгрегацияГистограммПоУмолчанию

Возвращает агрегацию гистограмм по умолчанию для этого читателя.

**Возвращает:** `Строка`, `Соответствие` — заданная для вида `Histogram` через
`УстановитьАгрегациюПоУмолчанию` или `"explicit_bucket_histogram"`

---

### ВременнаяАгрегацияДляВида

Возвращает временную агрегацию потоков читателя: Prometheus принимает только кумулятивные данные.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `ВидИнструмента` | `Строка` | — | Вид инструмента |

**Возвращает:** [`ОтелВременнаяАгрегация.Кумулятивная()`](./ОтелВременнаяАгрегация.md)

## Пример

```bsl
// Настройка Prometheus-читателя
ПрометеусЧитатель = Новый ОтелПрометеусЧитательМетрик();

Построитель = Новый ОтелПостроительПровайдераМетрик();
Построитель.ЗарегистрироватьЧитатель(ПрометеусЧитатель);
Провайдер = Построитель.Построить();

// В HTTP-обработчике /metrics: формат выбирается по заголовку Accept запроса
ТипКонтента = "";
ТелоОтвета = ПрометеусЧитатель.СобратьДляЗапроса(ЗаголовокAccept, ТипКонтента);
// ТипКонтента => "application/openmetrics-text; version=1.0.0; charset=utf-8; escaping=underscores"
//   для Accept: application/openmetrics-text;version=1.0.0
```
