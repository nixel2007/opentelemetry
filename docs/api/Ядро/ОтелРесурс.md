# ОтелРесурс

Класс описания ресурса (Resource) по спецификации OpenTelemetry.

## Описание

Ресурс описывает сущность, производящую телеметрию: сервис, хост, процесс и т.д. По умолчанию при создании добавляются обязательные атрибуты: `service.name`, `telemetry.sdk.name`, `telemetry.sdk.language`, `telemetry.sdk.version`. Атрибуты можно дополнить через [ОтелПостроительРесурса](./ОтелПостроительРесурса.md).

## Конструктор

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `БезУмолчаний` | `Булево` | `Ложь` | Если `Истина`, не добавлять атрибуты по умолчанию |
| `АдресСхемы` | `Строка` | `""` | URL схемы ресурса. Если не задан, у ресурса с атрибутами по умолчанию — схема семантических соглашений детекторов ресурса |
| `БезОкружения` | `Булево` | `Ложь` | Если `Истина`, атрибуты по умолчанию не дополняются из `OTEL_RESOURCE_ATTRIBUTES` и `OTEL_SERVICE_NAME` (так ресурс создаёт файловая конфигурация) |
| `НачальныеСущности` | `Массив` из [`ОтелСущность`](./ОтелСущность.md) | `Неопределено` | Сущности ресурса (Entities, статус Development). Ресурс создаётся как ресурс с атрибутами, слитый с ресурсом из этих сущностей: атрибуты сущностей перезаписывают атрибуты по умолчанию. Невалидная сущность пропускается с ошибкой в логе |

### Сущности

Ресурс может состоять из сущностей ([Entities](https://opentelemetry.io/docs/specs/otel/entities/data-model/),
статус Development) — например `service` или `host` — и атрибутов, не связанных с сущностями.
Атрибуты сущностей (идентифицирующие и описательные) входят в атрибуты ресурса, поэтому
экспортируются как обычные атрибуты ресурса; ссылки на сущности (`entity_refs`) в OTLP пока не
передаются.

Если хотя бы у одного из сливаемых ресурсов есть сущности, `Слить` работает по алгоритму модели
данных ресурса:

- сущности другого ресурса сливаются по очереди: сущность того же типа с той же идентичностью и
  адресом схемы объединяет описательные атрибуты (значения новой приоритетнее); сущность того же
  типа с другой идентичностью или схемой заменяется вместе со всеми своими атрибутами; иначе
  сущность добавляется, перезаписывая атрибуты;
- затем сливаются атрибуты другого ресурса, не принадлежащие его сущностям;
- атрибут принадлежит только одной сущности: сущность, атрибут которой перезаписан, удаляется из
  ресурса, её остальные атрибуты остаются атрибутами ресурса.

```bsl
Сущности = Новый Массив();
Сущности.Добавить(Новый ОтелСущность("host", Новый Структура("host.id", "H1")));
Старый = Новый ОтелРесурс(Истина, "", Истина, Сущности);

Обновляющий = Новый ОтелРесурс(Истина);
Обновляющий.Атрибуты().Установить("host.id", "H2");

Результат = Старый.Слить(Обновляющий);
// Сущности(): пусто - атрибут host.id сущности host перезаписан; host.id = "H2"
```

## Методы

### Атрибуты

Возвращает атрибуты ресурса.

**Возвращает:** `ОтелАтрибуты` — атрибуты ресурса

---

### АдресСхемы

Возвращает URL схемы ресурса.

**Возвращает:** `Строка` — URL схемы или пустая строка

---

### Сущности

Возвращает сущности ресурса (см. [Сущности](#сущности)).

**Возвращает:** `ФиксированныйМассив` из [`ОтелСущность`](./ОтелСущность.md)

---

### Слить

Создает новый ресурс как результат слияния текущего с другим. Атрибуты другого ресурса имеют
приоритет. Если у одного из ресурсов есть сущности, слияние идёт по алгоритму модели данных ресурса
(см. [Сущности](#сущности)).

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `ДругойРесурс` | `ОтелРесурс` | — | Ресурс для слияния |

**Возвращает:** `ОтелРесурс` — новый ресурс со слитыми атрибутами

---

### ВСоответствиеOtlp

Преобразует ресурс в соответствие формата OTLP JSON.

**Возвращает:** `Соответствие` — `{"attributes": [...]}`

## Пример

```bsl
Ресурс = Новый ОтелПостроительРесурса()
    .Установить("service.name", "мой-сервис")
    .Установить("service.version", "1.0.0")
    .УстановитьАдресСхемы("https://opentelemetry.io/schemas/1.24.0")
    .Построить();

ИмяСервиса = Ресурс.Атрибуты().Получить("service.name"); // "мой-сервис"
```
